# 中英文阅读

读者可用右上角“中 / EN”切换。每次新打开或刷新网站默认中文，主动切换后的选择仅在当前页面会话及站内跳转中保留，不要求登录，也不改变收藏ID、已读、精选、事件归组、发布时间或中文原稿。搜索仍使用原文索引；英文公司名等原文已有词可检索，暂不做跨语种语义搜索。

普通读者界面、资讯标题/摘要/推荐理由、日报（以及周月报已出版部分）的正文使用英文呈现。信源名、品牌标识、来源原文和已确认的法律文档正文保留原文。译文为阅读辅助，缺失或接口不可用时显示中文原文，页面提示译文待补。中文页面仍为搜索引擎的规范版本，不另建英文URL或更改RSS/API约定。

界面常用短标签在 `modules/language/ui.ts`；其余界面文字及含 `{{0}}` 插值的文案在 `ui-source.json` / `ui-patterns.json`。新增界面文案应同时补入这些目录。资讯、日报正文使用 `<Text content>`，完整匹配原文，不应用界面插值模板；界面模板仅用于较明确的提示文案。`Text` / `useText` 是通用展示插口，未安装语言模块时返回原文，不依赖DOM改写或第三方网页翻译。

译文按完整原文的SHA256存到 `language_texts`，原文更正后不复用旧译文。公开查询每个IP每分钟最多60次，每次最多64条原文、128KB正文，先经统一publication层核对当前公开范围，再读取已有译文，不触发模型或排队；公开范围缓存最长30秒。撤稿不再对外提供对应译文，数据库保留审计回执。报告通过 `loadReport` 读取，撤稿引用先被排除，不把数据库中的原始历史报告直接公开。

worker任务 `language.translate` 每两小时分批补译，优先界面与最近刊物，再处理资讯。每批最多24段、约1800中文字，按独立id对齐，乱序不会串稿、缺条不接纳；使用现有 `deepseek-flash`，校验条数、数字实际数值（允许万元/million、月份名称与千分位等值转换）、版本、URL与占位符，并在事务中保存译文及完成付费回执。单段不合格时不公开，延后24小时再试，最多三次；其余合格段继续入库，不因一段坏结果卡住全部补译。无可用译文时不凭空生成要闻。所有费用计入现有总预算，金额/次数/停用/未知付费结果保护均不绕开；达到总预算会延期，不能承诺0.5元覆盖全部处理与英文补译。

开发阶段需要补译历史时，在当前云端发布目录执行：

```bash
sudo docker compose exec -T api node modules/language/scripts/backfill.ts --batches=1
```

批数可设1到500。仍受同一模型预算和回执控制；不要并行启动多个补译进程，也不要直接调用提供商绕开预算。先检查worker是否正执行该翻译任务，等其完成后再手动补译。不会修改已出版日报的中文快照。
