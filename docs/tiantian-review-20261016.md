## 已修复的稳定性问题

- 事件展开请求增加 15 秒超时；网络失败、无效响应可重试，不让异常对象进入渲染。
- 已有内容刷新失败时明确提示“当前为上次内容”，不会把旧内容当更新成功。
- 手机重新打开事件面板会刷新；内容撤回或空结果不继续显示旧列表。
- 全文相关排序可能让同一天出现多个不连续区段，区段 key 加上首条文章 ID，避免 React 重复 key。
- 事件归组和综述任务因预算耗尽而用尽队列重试后，恢复扫描在失败满一小时后重试同一任务；并发事务锁防重复，其他错误不自动复活。每次调用仍走原预算检查和付费回执。

## 开发阶段预算（用户本轮明确授权）

本机 `.env` 的 `LLM_DAILY_BUDGET_CNY=unlimited`。整个开发阶段不限金额，跨北京时间午夜不恢复原 0.5 元限制，继续使用 DeepSeek Flash 已核验单价记录估算费用。`.env.example` 保留 0.5 元默认值，正式运行前重新确定限额。

请求速率保护保留：12 次/分钟；为开发清理积压，小时/日吞吐额度从 60/1000 调为 1000/10000。保留重试、费用记录和防重复调用。变更已记入本地审计，未输出或修改 API 密钥。

115 篇预算等待材料已重新入队，5 个超过冷却期的预算失败事件任务已恢复。之后只读抽查显示等待材料降至 108 篇，近五分钟有 19 次收到响应的模型请求；说明恢复在运行，**不代表所有积压已经完成**。处理中的材料仍按相关性规则过滤，不保证全部入库发布。
